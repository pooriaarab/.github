# Support

This is the default support policy for every repository under
[@pooriaarab](https://github.com/pooriaarab).

## Where to go

| You want to | Go to |
|---|---|
| Report something broken | An issue on that repository. |
| Ask how something works | The repository's README first, then an issue. |
| Report a vulnerability | [SECURITY.md](SECURITY.md). Not an issue. |
| Propose a change | An issue, before you write the code. |

## Before you open an issue

Read the README. Most of these repositories answer the common question in the
first screen, and an issue that the README already answers is slower for you
than reading it.

Search the closed issues too. A question asked once has usually been asked
twice.

## What makes an issue answerable

State what you cannot do today, what you expected, and what happened instead.
Then give the steps that reproduce it, and the version, operating system and
runtime you are on.

"It does not work" cannot be answered. It can only be replied to with a request
for the information that should have been in the first message, which costs you
a day.

## What to expect

These are side projects maintained by one person, mostly at night. There is no
service level agreement and no paid support tier.

- A bug with clear reproduction steps gets looked at.
- A feature request gets read, and usually gets a plain answer about whether it
  fits the project. A no is not a rejection of the idea. Every repository has a
  `VISION.md` that states what it is explicitly not, and that file is the reason
  for most of the noes.
- An issue with no reproduction and no reply from its author gets closed after a
  while. Reopen it whenever you have more.

## Commercial use
